# WordCat Next：研發分支方向

這個分支從 2.0.2 的 `master` 分出來，用來做比較大膽的改造，不直接合回 `master`。
方向參考 Epop 的學習流程（2026-11-05 錄的 7 段影片），但只取它背後的原理，
不照抄它的畫面、文字或內容。

---

## 0. 這個分支的規則

### 兩條主線，同一個 App

- 研發版和正式版是**同一個 App**（`com.rio.word7000`），這樣正式版累積的評分、評論和下載都留著，使用者的進度也是同一份。
- `master` 是 **2.0.x**，這個分支是 **3.0.0**。TestFlight 的建置號碼是「每個版本各自從 1 開始」，
  所以兩條線各有自己的號碼，不會互相搶：例如正式版 2.0.2 (8)、研發版 3.0.0 (1)。
  這也讓 `master` 送審、上架 2.0.x 完全不受影響。
- **發研發版到 TestFlight**：GitHub Actions → `iOS release` → Run workflow，
  「Use workflow from」選這個分支，operation 選 `native-testflight`。
- **TestFlight 群組**：研發版發給 `WordCat Lab` 群組。這個分支的發布流程預設就是它，群組不存在時會自動建立，
  而且 3.x 的建置發給公開群組（`Wordcat Public Testing 1`）會直接失敗。
- 兩條線的完整規則寫在 `CLAUDE.md` 的「兩條版本線」，每個對話一開始都會讀到，以那裡為準。
- **換線**：Apple 只要核准過某個版本，之後上傳的版本號都必須比它高。3.0 一被 App Store 核准，2.x 就傳不上去了，
  所以研發版上架那一刻，就是把研發分支合進 `master`、只剩一條線的時候。

### 不自動上線

- 這個分支的名字不是 `master`，也不是 `native/**`，所以 push 時：
  - `ios-native.yml` 不會自動跑，要測就手動按 workflow_dispatch。
  - `ai-backend.yml` 不會部署 Supabase（它只在 `master`、`native/**` 上部署，**這個分支千萬不要改名成 `native/...`**）。
  - Cloudflare 只會為這個分支建預覽網址，正式網站的 `public/` 不受影響。
- **後端只有一套，只從 `master` 部署。** `ai-backend.yml` 也可以手動在這個分支上跑，但那會用研發版的
  `supabase/` 蓋掉正式後端。研發版需要的後端改動，要寫成「只新增、不改舊的」，先合進 `master` 再部署。

### 進度資料要能來回切換

測試者可能從正式版換到研發版，也可能被 TestFlight 換回正式版。兩邊讀寫的是同一份本機資料和同一份雲端進度（`profiles.progress` 是整份覆寫），所以：

- 只能**新增**欄位，不能改舊欄位的意思或格式。
- 研發版新增的資料，要能承受「被正式版寫回時弄丟」。重要的新資料要另外存，不要只塞在進度裡。
- 不做只能往前、不能往回的資料搬移。

### 學習規則只寫 Swift

App 本來就是 100% 原生 SwiftUI。`master` 另外保留了一份舊 React Native 時代的 TypeScript 學習規則（`src/lib/`），
當作規格，Swift 用測試比對它。這個分支新的學習規則**只寫在 `Word7000Core`（Swift）**，只寫 Swift 測試，不再兩邊各寫一次。
既有的 TypeScript 規則和比對測試先不動，改到它們時再一起移除。

## 1. Epop 為什麼直覺、讓人一直想玩：八個原理

1. **一個畫面只有一個主要按鈕。** 開始 → 繼續 → 下一題 → 繼續測試。App 決定接下來做什麼，使用者不用選模式。
2. **自己打出來，而且有情境。** 上面中文句子、目標詞標色；下面英文句子挖空。每題 5～10 秒，答對是「自己掙來的」，比翻卡自評有成就感得多。
3. **難度跟著你跑，讓你大多數時候答得出來。** 2級 → 4 → 6 → 9 → 12 → 15 → 18，答對就跳，還會說「你的程度不錯，接下來會更難」。
4. **失敗不是死路。** 首字母提示 → 看答案 → 自己重打 → 「5分鐘後複習」。每次失敗最後都變成一次「自己打對」，而且知道什麼時候會再見到它。
5. **錯了會告訴你錯在哪。** 「ass 是『屁股』的意思。『自負』該怎麼說呢？」它解讀的是你打的那個字，不是只說「錯」。
6. **進度在每個時間尺度都看得見。** 題內（卡片變色）、這一輪（頂部 n/20 和里程碑星星）、這週（連續學習週曆）、長期（年度熱力圖、已知單字數）、身分（CEFR 等級、排名）。
7. **永遠留一個沒完成的事。** 「CEFR ??」「再完成 13 題看排名」「5分鐘後複習」，首頁主按鈕是「繼續測試」。
8. **典禮感。** 全螢幕深色背景、星星爆開、數字跳動、火焰點燃；轉場時吉祥物出來講一句，關鍵字上色。

## 2. 我們已經有、Epop 沒有的優勢（不要丟）

- **明確的終點**：學測 7000 字、14 個 Core 級。「已掌握 N / 7000」和「距離學測 N 天」比 Epop 的「全國排名」更真實、更有壓力也更有意義。
- **嘴賤的貓**：比 Epop 的通用吉祥物有個性，好笑的台詞本身就是獎勵。
- **紙張筆記本的質感**：Epop 的紫色是很普通的教育 App 風格；我們的視覺有辨識度，只是缺少「遊戲感」。
- **核心永遠免費**、口說練習（裝置上辨識）、拍講義掃單字、雙向（學英文／學中文）。
- **資料已經準備好**：7000 個例句中有 6998 句原封不動含有該單字，可以直接挖空；4851 句的中文例句直接包含中文意思，可以直接標出提示詞。

## 3. 學習形式

> **方向（2026-11-05 第三版，取代前兩版）**：App 有兩大支柱：**單字**和**口說**。拼字、小測驗、模擬考不再是獨立入口，
> 融進這兩個的學習程序。翻卡（今天的單字）是原本的重大特色，介面和操作保留，當作單字程序的第一步。
> 介面可以重新排，但沿用現有風格（紙張、皮革、陶土色、拼貼膠帶、會走動的貓）。索引標籤、書桌、一疊卡三個方案都作廢。

### 3.1 單字的學習程序：翻卡 → 拼字 → 考考看

| 步驟 | 做什麼 | 哪些字 | 結果怎麼算 |
|---|---|---|---|
| 🃏 翻卡 | 現有的翻卡，完全不變 | 今天的字：新字＋到期複習 | 認識／不熟（自己判斷）；不熟的在這一步裡再翻一次 |
| ✍️ 拼字 | 看中文提示，打出句子裡的字（沒有例句的字改成看意思打單字） | 這次按「認識」的新字，和還在學的字（第 1～2 階） | 對：照排程；錯：被抓包，改回不熟 |
| 📝 考考看 | 學測題型：句子挖空四選一，選項是容易混淆的字（adapt／adopt） | 這次按「認識」、已經學一陣子的字（第 3 階以上） | 對：照排程往後；錯：被抓包，改回不熟 |

- 這就是「翻單字卡之後融合拼字練習」：**你按認識的字，都會被用適合它的方式抽查**。剛學的字考拼寫，學過一陣子的字考學測題型。
- 份量有上限，整個程序約 10 分鐘：拼字最多 6～8 題、考考看最多 5 題，其餘按「認識」的字照翻卡的結果算（抽查，不是全考）。
- 按「不熟」的字當天不再進後面兩步，避免挫折，明天再出現。
- 結束畫面沿用現有的，加一行：本來就會・新學・被抓包。被抓包的字之後在首頁的「被抓包的字」小卡可以加練。

**原本的功能去哪了：**

| 原本 | 現在 |
|---|---|
| 今天的單字（翻卡） | 單字程序的第一步，不變 |
| 拼字練習 | 單字程序的第二步（句子挖空） |
| 小測驗（四選一） | 單字程序的第三步改成學測題型；想單獨考，長按單字卡選「考 10 題」 |
| 複習不熟的字 | 每天的字本來就先排它們；另外首頁的「被抓包的字」小卡 |
| 模擬考 | 每週日的「週考」（這週學過的字，10～20 題學測題型）；完整的 50 題限時模擬考保留（Premium），考試前一個月出現在首頁，平常從單字卡長按進去 |

### 3.2 口說的學習程序：聽 → 跟讀 → 回答 → 用今天的字

- 現有的口說關卡（情境、星星）保留，每一關變成四小步：先**聽**一遍對話，**跟讀**（現有），**回答**問題（現有，Premium 有 AI 修改建議），
  最後**用今天的字**：挑 1～2 個今天單字程序學的字，說一句話。這一步把兩個支柱接起來，也取代現在獨立的「單字口說」。
- 口說裡聽不懂或說不出的字，會回到單字的複習裡。
- 每幾關有一個「關主關」：一段完整的對話，算是口說自己的考試。

### 3.3 介面：兩張會長大縮小的主卡

- 首頁只有兩張主卡：**單字**（皮革色）和**口說**（苔綠色）。現在最該做的那張是大卡（圓環、步驟、主按鈕），另一張縮成一行。
- 做完一張，另一張自動長大；兩張都做完，都縮成一行打勾，加上「加碼」和慶祝。
- 大卡上的步驟可以直接點，想跳過翻卡直接拼字也可以：**主按鈕負責引導，步驟負責彈性。**
- 貓坐在現在推薦的那張卡上，點貓就聊天。
- 主卡下面的情境小卡，只有用得到的時候才出現：被抓包的字、週日週考、講義小考（拍講義加的字庫有考試日時）、考前一個月的大考模擬。
- 長按單字卡：只翻卡、只拼字、考 10 題、換字庫。不佔畫面，又保留自由。
- 現有的練習方塊收掉（功能已經融進程序）。字庫切換移到單字卡上的小標籤；三個分頁（今天、單字、我）、問候、連續天數、EN／中 切換都保留。
- 練習畫面上方有步驟條（翻卡 ✓ → 拼字 2/6 → 考考看），中途離開會從原處繼續。

### 3.3.1 之後可以讓學習更「無感」的地方

- 主畫面小工具上直接翻卡（認識／不熟兩個按鈕），不用打開 App 也能累積今天的進度。
- 鎖定畫面的即時動態顯示下一張卡。

### 3.4 拼字題（挖空）的細節

**一組拼字題的排法：**

- 開頭先放 2 題容易的複習（暖身先贏），結尾也放一題容易的（結束時感覺好）。
- 目標答對率約 80%：連錯 3 題就插一題簡單的；連對 5 題又答得快，就往上一級出題（沿用現有的 `estimateAbility`）。
- 答錯的字在同一輪 3～4 題後再考一次（翻卡模式已經有 `requeueGap = 4`）。

**答錯時的解讀**（完全離線，依序判斷）：

1. 大小寫、空白不同 → 算對。
2. 是同一個字的變化形（打了 adapted，題目要 adapt）→「字對了，這裡要用 adapt」。
3. 只差一個字母或兩個字母對調 →「差一點」（現在拼字練習已經有）。
4. 打出的是字表裡的另一個字 →「ass 是『屁股』。『自負』是哪個字？」
5. 都不是 → 給首字母。
6. 之後再做：同義字（意思對但不是這句用的字），需要同義詞資料或 AI。

**提示順序**：字長（預設就有）→ 首字母 → 再一個字母 → 看答案 → 自己重打。
用了 2 個以上提示才答對，只算練習、不移動排程（現在的規則）。

**每題答完：**

- 對：整張卡染成鼠尾草綠、蓋章動畫、觸覺回饋、短音效，自動念整句。
- 卡片角落出現下次見面的時間：「3 題後再考」「明天見」「7 天後見」，讓間隔複習看得見。
- 下方工具列：重聽、慢速、單字詳情、問貓老師（Premium）。

### 3.5 新手引導：保留現在的三步，只做小改動

現在的新手引導（選學英文或中文 → 每日目標 → 9 個字選認識的）保留。只改：

1. 每日目標那一步順便問「你在準備什麼考試？」（學測、會考、統測、英檢、多益、沒有考試），用來顯示倒數、建議每日目標。
2. 9 個字裡選「認識」的，馬上抽 2～3 個用拼字抽查，第一次就讓使用者看到抽查是什麼。
3. 通知權限改在第一次做完單字程序後才問：先讓使用者選提醒時間，再跳系統的詢問。

### 3.6 進度看得見：主數字「已掌握 N / 7000」

這一節和 3.7 都是之後的項目；現有的連續天數、稱號（單字新手到單字傳奇）、結束畫面都沿用，只是往這個方向加強。

| 時間尺度 | 顯示方式 |
|---|---|
| 一題 | 卡片染色、蓋章 |
| 一輪 | 頂部進度條，一半處有里程碑星星 |
| 一天 | 首頁圓環 x/20 |
| 一週 | 連續學習週曆條（一～日，火焰；第 7 格是獎勵） |
| 長期 | **已掌握 N / 7000**、14 章地圖（每章 500 字）、年度熱力圖 |
| 身分 | 你的程度（Core X），升級時有全螢幕典禮 |

「已掌握」要有清楚的定義（例如到達第 4 階以上），數字只會因為真的學會而增加。

### 3.7 典禮與回訪

**結束畫面**：沿用現有的（圓環、彩帶、貓評語、按鈕），內容依序加強；以下是之後可以加的項目，不是一次全做：

1. 「完成！」答對數字跳動。
2. 「本來就會 6｜新學 4｜明天複習 3」。
3. 連續學習火焰 +1，週曆條點亮今天。
4. 里程碑（有才出現）：已掌握破 1,000、一章完成、程度升級。
5. 貓的評語（現有的 AI verdict，或離線台詞）＋分享卡（IG 限動尺寸：「今天背了 20 個字，學測倒數 75 天」）。

**連續學習**：

- 現在已經有「每 7 天可以漏 1 天」的保護。把它畫成道具「貓罐頭」：貓吃掉一個罐頭，幫你保住紀錄。規則先不改，只是看得見。
- 晚上 9 點還沒學：通知用貓的口氣提醒（現在已有最後一小時的 Live Activity）。

**變動獎勵**（不需要商店或貨幣）：隨機的貓台詞、程度升級畫面、每 500 字一章完成的徽章、100／500／1000／3000 字的里程碑。

## 4. 視覺設計

**沿用現有風格**：紙張和皮革、陶土色、襯線字、拼貼膠帶、會走動的貓都不改，也不做 Epop 那種紫色或分頁標籤。
答題畫面沿用現有元件（進度條、卡片、底部按鈕列），只在答對、答錯時讓卡片染色。

**只加三個記號，讓新功能看起來是同一套：**

- **螢光筆**：目標詞在中文句和英文句都用手繪邊的螢光筆標出（取代 Epop 的綠字）。
- **印章**：答對蓋「✓」章，連對蓋特別的章。
- **貼紙**：做完的步驟、做完的主卡。
- **聲音**：鉛筆打勾、蓋章、翻頁，都很短；設定可關閉。
- 每個回饋都配觸覺；開啟「減少動態效果」時改用淡入淡出。

**貓只在轉場出現**（開場、升級、結束、要離開時），答題中不擋畫面。泡泡裡的關鍵字上色。

## 5. 策略

- **定位**：Epop 什麼都教、對象模糊；WordCat 專注在「考試單字 + 嘴賤貓 + 免費」。主數字跟考試綁在一起。
- **收費**：
  - 核心永遠免費，這是我們跟 Epop 最大的差別，也是賣點。
  - 不做付費分頁。付費入口放在「想要的那一刻」：答錯後「為什麼不是 X？問貓老師」、結束畫面「看你最常錯在哪一類」。
- **通知權限**：`master` 是開 App 就問。這個分支試另一種：第一次完成之後、先讓使用者選好時間再問。這正是研發分支適合做的對照實驗。
- **要看的數字**：開 App 到第一題的秒數、第一天完成第一輪的比例、第 1 天／第 7 天回來的比例、每天幾輪、通知同意率。App 已經有使用數據（`usage_events`：只記錄有登入的使用者、按天加總，`remote-usage.yml` 看得到回訪率），研發版補上缺的事件，並分得出是 3.0 的資料（見第 8 節）。

## 6. 不做的事

- 聯賽、好友、鑽石、商店、修正筆這一整層：伺服器、配對、防作弊的成本都高，也容易讓人為了分數刷簡單題。之後真的要做社交，再評估「班級排行」。
- 哭臉挽留、「一天沒學紀錄就重置」這類罪惡感設計，用貓的吐槽代替。
- 沒有真實資料支撐的「全國排名」「贏過 82% 的人」。
- 問了卻沒用上的問卷。
- 自製鍵盤：系統鍵盤加上關閉自動修正就夠，按鈕放在鍵盤工具列；自製鍵盤的無障礙成本太高。
- 影劇台詞當例句（版權）。

## 7. 路線圖

### 第 0、1 步做了什麼（2026-11-05）

- **中文提示詞**：`content/example-cues.json`，7,000 個字都有。5,565 個用字義比對找到，其餘由 AI 逐句標註後抽查。
  11 個字的中文沒有直接對應的部分（of、be……），畫面改成顯示中文意思。同一句出現兩次的，用「前文|提示詞」指定是哪一個。
  `scripts/export-native-words.mjs` 會把它寫進 `words.json` 的 `exampleZhCue`；例句改過、對不上的提示詞會被略過並列出來。
- **引擎**（`Word7000Core/Cloze.swift`，測試在 `ClozeTests.swift`）：
  - `Cloze`：把例句挖空（句子裡每個出現的地方都挖），找出要標螢光筆的中文，判斷打的答案：對、對的字但形式不對、
    打成字表裡的另一個字（說出它的意思）、差一個字母、錯。
  - `ClozeAttempt`：一題的過程。先給第一個字母，再給答案；錯三次會自動出現答案；看了答案還是要自己打。
    一次就對＝本來就會，給了第一個字母或錯一次＝有一點幫忙，更多＝沒記住。
  - `ClozeRound`：一輪的順序。兩個熟的複習字開場、一個收尾；沒記住的字 3 題後再考一次（最多半輪）；
    連錯 3 題就把最簡單的字拉到下一題；結束時算出本來就會、新學、複習、沒記住各幾個。
- **畫面**（`Views/ClozeSessionView.swift`）：「今天」頁最上面的「挖空練習」方塊（只在學英文模式）。答對整張卡變綠、蓋章，
  標出「等一下再考你／明天見／N 天後見」。結束畫面顯示本來就會、新學、複習三個數字。
- **記錄進度**：一次就對 → `markKnown`（新字直接跳到 7 天後），有一點幫忙 → `markQuizCorrect`，沒記住 → `markReview`。
  使用數據多了 `cloze_round`、`cloze_answer` 兩個事件。

**還沒做、留給之後**：學中文模式的挖空題、回饋音效、遠端修正例句時一起修提示詞。臨時的「挖空練習」方塊會在第 2、3 步併進單字程序後收掉。
